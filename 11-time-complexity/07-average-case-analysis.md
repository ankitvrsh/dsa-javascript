# Average Case Analysis

## Average Case : Big Theta (Θ)

In this, we take an overall average of multiple operations by summing up the results of all the operations and then dividing it by the number of operations done.  
This will help us to get an average number of instructions that goes on per operation.  
In this, we just take a look at the overall average picture of the algorithm.

There are special algorithms, for example: Quick Sort.

Quick Sort relies a lot on the Average Case Complexity.  
Because the worst case complexity of Quick Sort is very bad.  
But the probability of occurrence of the worst case of Quick Sort is very less that sometimes we can say that it will never even occur.

The probability is so less that the worst case of Quick Sort doesn’t make it a very bad option.

That’s why, we choose Quick Sort because of the average case because on an average, Quick Sort performs very good.

Similar thing exists with addition of new elements in arrays.  
There is a very efficient way to perform this operation.  
But this efficient way sometimes perform very bad and sometimes perform very good.  
That’s why, we are not able to analyse it.  
That’s why, we rely a lot on the Average Case Analysis.

Big Theta works on an average, i.e. overall how does the performance of the algorithm looks like.
